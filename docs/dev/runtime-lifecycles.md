# Runtime lifecycles

This audit covers application-owned lifecycle state in the GUI, core, daemon,
and input backends. Cross-platform entries describe the
source paths. Native verification in this pass used macOS with isolated settings
and local sockets. Windows service sessions, X11 selections, Wayland portal
sessions, and physical input transitions need their respective environments.

## Observable behavior

| Lifecycle and state owner | Transitions, effects, and ordering |
| --- | --- |
| GUI startup, tray and exit ([MainWindow](../../src/lib/gui/MainWindow.cpp)) | The persisted role, autostart preference, and window state drive startup. Closing can hide to the tray. Quitting invokes desktop process cleanup. GUI controls use the process phase and connection status together. |
| Settings and migration ([Settings](../../src/lib/common/Settings.cpp), [ServerConfig](../../src/lib/gui/config/ServerConfig.cpp)) | Settings and transient state use separate stores. Startup imports old groups and array entries into canonical settings. Existing destination values win. Config dialogs edit copies and save on acceptance. The core reads config and settings at start or explicit reload. |
| Computer grid and shortcut editor ([ComputerSetupModel](../../src/lib/gui/ComputerSetupModel.cpp), [KeySequenceWidget](../../src/lib/gui/widgets/KeySequenceWidget.cpp)) | Drag and drop modifies the draft grid after validating the origin and destination. The recorder captures keys only while recording and restores its display on stop. Persisted topology changes through settings save. |
| GUI process lifecycle ([CoreProcess](../../src/lib/gui/core/CoreProcess.cpp)) | The GUI owns process intent, last mode, and a restart timer. In desktop mode QProcess owns actual launch and exit. In service mode the GUI sends intent after daemon IPC connects. Process Started and network Connected can occur independently. |
| Duplicate core and stale version ([CoreProcess](../../src/lib/gui/core/CoreProcess.cpp), [CoreIpcServer](../../src/lib/deskflow/ipc/CoreIpcServer.cpp)) | A duplicate exit triggers a probe. A matching core is left running. A mismatched core accepts Stop and sends `bye`. The probe schedules a replacement after observing shutdown. |
| GUI IPC client ([IpcClient](../../src/lib/gui/ipc/IpcClient.cpp)) | Socket establishment precedes the version exchange. Refusal at the transport stage enters retry backoff. The version exchange can succeed, mismatch, fail, or expire. A mismatch permits Stop. Explicit disconnect cancels the timer and discards partial input for that connection. |
| Core and daemon IPC server ([IpcServer](../../src/lib/deskflow/ipc/IpcServer.cpp), [CoreIpc](../../src/lib/deskflow/ipc/CoreIpc.cpp), [DaemonIpcServer](../../src/lib/deskflow/ipc/DaemonIpcServer.cpp)) | Transport membership, waiting broadcasts, and version exchange are separate facts. A matching `hello` drains the pending broadcast list to that peer. Core status is copied to the GUI over this channel. A command being sent grants no acknowledgement that the daemon completed the request. |
| Status bar, network and update indicators ([StatusBar](../../src/lib/gui/widgets/StatusBar.cpp), [NetworkMonitor](../../src/lib/gui/core/NetworkMonitor.cpp), [VersionChecker](../../src/lib/gui/VersionChecker.cpp)) | Status text and retry countdown derive from core messages. A polling timer publishes only a changed interface list. An update response is compared with the current version before announcing availability. |
| Log tail ([FileTail](../../src/lib/gui/FileTail.cpp)) | A watcher and open file share the observed path. The file offset starts at the end and advances after each change callback. Rotation, truncation, and failed reopen are separate from core connection state. |
| Daemon and Windows service supervision ([DaemonApp](../../src/apps/deskflow-daemon/DaemonApp.cpp), [ArchDaemonWindows](../../src/lib/arch/win32/ArchDaemonWindows.cpp), [MSWindowsWatchdog](../../src/lib/platform/MSWindowsWatchdog.cpp)) | Daemon IPC sets subprocess intent and settings. Watchdog state also depends on the Windows session, running process, and delayed restart. Service stop and session changes reconcile the subprocess before releasing its handles. |
| Startup event publication ([EventQueue](../../src/lib/base/EventQueue.cpp)) | Producers enqueue before the backend buffer is initialized. The loop initializes the buffer, transfers startup events in FIFO order, then publishes readiness. The readiness predicate and transfer share the enqueue mutex. Quit ends an invocation. Server shutdown can invoke the loop again for drain. |
| Queue dispatch and timers ([EventQueue](../../src/lib/base/EventQueue.cpp), [IEventQueueBuffer](../../src/lib/base/IEventQueueBuffer.h)) | Event IDs bridge a platform buffer and payload table. Buffer adoption discards the old table. Dispatch copies a handler so it can remove itself while running. One-shots leave the priority queue on expiry; periodic timers rearm. Timer consumers own cancellation and target lifetime. |
| Socket worker ([SocketMultiplexer](../../src/lib/net/SocketMultiplexer.cpp)) | Add/remove updates the job set; a wakeup interrupts polling so the worker can see it. Poll interest derives from socket state. A completed job can replace or remove itself. Socket teardown must respect lock ordering with the worker. |
| TCP and TLS ([TCPSocket](../../src/lib/net/TCPSocket.cpp), [SecureSocket](../../src/lib/net/SecureSocket.cpp)) | A TCP connection, readiness to read or write, half-close, and TLS handshake completion have separate state. TLS builds on TCP. Peer verification and handshake success gate the secure-connected event. Errors and EOF shut down stream directions and retire jobs. |
| Packet framing and protocol negotiation ([PacketStreamFilter](../../src/lib/deskflow/PacketStreamFilter.cpp), [ClientProxyUnknown](../../src/lib/server/ClientProxyUnknown.cpp), [ServerProxy](../../src/lib/client/ServerProxy.cpp)) | The packet filter exposes a length-delimited frame when enough bytes are available. The listener waits for protocol negotiation before handing off the proxy. On the client, a proxy can exist while the initial options handshake is pending. Keepalive and timeout events are scoped to the corresponding connection. |
| Client startup, fallback, suspend and resume ([ClientApp](../../src/lib/deskflow/ClientApp.cpp), [Client](../../src/lib/client/Client.cpp)) | The app chooses a candidate host and resolved address, then schedules retries according to the failure and suspend state. The client owns transport, proxy, readiness and active input separately. Handshake completion enables the computer. Cleanup removes handlers and resets connection state before releasing the stream. |
| Server startup, reload, suspend and shutdown ([ServerApp](../../src/lib/deskflow/ServerApp.cpp), [ClientListener](../../src/lib/server/ClientListener.cpp)) | Primary initialization and listening are separate phases. Resources, retry timers, and suspend state complete the state enum. Accepted clients move from negotiation to a handoff queue and then into the server. Shutdown asks clients to disconnect and exits its drain loop on completion or deadline. |
| Peer membership and closure ([Server](../../src/lib/server/Server.cpp)) | A named peer is admitted after config and duplicate checks. Closing removes it from routing, then holds it until disconnect or timeout. Active-peer removal returns input to primary. Either removal path cancels a delayed switch targeting that peer. |
| Screen switching and relative motion ([Server](../../src/lib/server/Server.cpp), [Client](../../src/lib/client/Client.cpp)) | Edge selection stores a candidate, direction, delay timer and double-tap state. No neighbor, locked edges, switching or candidate removal clears a pending switch. A successful leave precedes active-peer assignment, sequence increment, enter and clipboard delivery. Relative mode keeps a separate restore position. |
| Screen lock and restoration ([Server](../../src/lib/server/Server.cpp), [Computer](../../src/lib/deskflow/Computer.cpp)) | The server remembers return peer and coordinates on screensaver activation and sends lock/unlock to peers. Disconnect while locked substitutes primary as a safe return target. Platform implementations own the actual OS effects. |
| Routed input and hotkeys ([InputFilter](../../src/lib/server/InputFilter.cpp), [Computer](../../src/lib/deskflow/Computer.cpp), [ServerProxy](../../src/lib/client/ServerProxy.cpp)) | Matched press and release actions can change focus, lock routing or broadcast. The receiver batches consecutive mouse updates and flushes before dependent input. Computer enable, enter, leave and fake-input scope determine when native effects can run. |
| Held keys and layout sync ([KeyState](../../src/lib/deskflow/KeyState.cpp), [ServerProxy1_8](../../src/lib/client/ServerProxy1_8.cpp), [KeyboardLayoutManager](../../src/lib/deskflow/KeyboardLayoutManager.cpp)) | Key-down resolves a native key and records the mapping for repeat and up. The receiver uses the negotiated language fields and available layouts. Teardown releases synthetic keys. Map state, modifiers and physical native keys can differ during a transition. |
| Clipboard owner, sequence and replication ([Server](../../src/lib/server/Server.cpp), [Client](../../src/lib/client/Client.cpp), [PrimaryClient](../../src/lib/server/PrimaryClient.cpp)) | Local ownership notification and bytes arriving are distinct events. The server tracks owner and sequence per selection; peer dirty/sent state suppresses redundant delivery. A switch flushes local clipboard information before entering the destination. |
| Clipboard transfer ([StreamChunker](../../src/lib/deskflow/StreamChunker.cpp), [ClipboardChunk](../../src/lib/deskflow/ClipboardChunk.cpp), [ClientProxy1_6](../../src/lib/server/ClientProxy1_6.cpp)) | The sender emits a declaration, ordered chunks of at most 512 KiB, and an end marker. Queued chunks own their bytes. The receiver tracks declaration, active state and accumulated data. It drains oversized transfers without appending and only publishes a completed size match. |
| macOS pointer handoff ([OSXComputer](../../src/lib/platform/OSXComputer.mm), [OSXCursorController](../../src/lib/platform/OSXCursorController.h), [OSXServerCursorMotion](../../src/lib/platform/OSXServerCursorMotion.h)) | The event thread owns visibility and parking phase. The HID tap checks the generation token, routes physical deltas separately, and reports completion. Returning invalidates the token before showing the cursor. A matching delivery can schedule the show-before-hide refresh. |
| macOS event tap, permission, lock and power ([OSXComputer](../../src/lib/platform/OSXComputer.mm), [OSXScreenSaver](../../src/lib/platform/OSXScreenSaver.cpp), [OSXPowerManager](../../src/lib/platform/OSXPowerManager.cpp)) | Accessibility and tap readiness gate capture. Power watcher readiness precedes event-queue readiness, then the run loop starts. Sleep confirmation and resume cross threads. Lock polling publishes observed changes. The pasteboard change counter tracks local clipboard ownership and change. |
| macOS input source, secure input and media keys ([OSXKeyState](../../src/lib/platform/OSXKeyState.cpp), [OSXComputer](../../src/lib/platform/OSXComputer.mm), [OSXMediaKeySupport](../../src/lib/platform/OSXMediaKeySupport.m)) | Layout selection and forwarded key state accompany enter/leave. Secure input detection can publish a notification. Media-key down and up follow the native event path. These effects depend on the current native session and permissions. |
| Windows desktop attachment and input hooks ([MSWindowsDesks](../../src/lib/platform/MSWindowsDesks.cpp), [MSWindowsHook](../../src/lib/platform/MSWindowsHook.cpp), [MSWindowsComputer](../../src/lib/platform/MSWindowsComputer.cpp)) | Desktop-change notifications and polling track a desktop, its thread, and hook state. Enable and enter/leave affect capture and foreground restoration. Shutdown stops desktop threads and detaches hooks. |
| Windows key and clipboard behavior ([MSWindowsKeyState](../../src/lib/platform/MSWindowsKeyState.cpp), [MSWindowsKeyRouting](../../src/lib/platform/MSWindowsKeyRouting.h), [MSWindowsClipboard](../../src/lib/platform/MSWindowsClipboard.cpp)) | Saved modifiers, dead-key composition and local Korean IME suppression affect paired input events. Clipboard open/close and ownership notifications govern when captured data gets forwarded. |
| Windows power and screensaver ([MSWindowsPowerManager](../../src/lib/platform/MSWindowsPowerManager.cpp), [MSWindowsScreenSaver](../../src/lib/platform/MSWindowsScreenSaver.cpp)) | Native events and a watcher update suspend or saver state. The screen saver implementation maintains settings to restore when disabling synchronization or closing. |
| X11 input capture and keyboard ([XWindowsComputer](../../src/lib/platform/XWindowsComputer.cpp), [XWindowsKeyState](../../src/lib/platform/XWindowsKeyState.cpp), [XWindowsEventQueueBuffer](../../src/lib/platform/XWindowsEventQueueBuffer.cpp)) | Enter and leave change grabs, focus and autorepeat state. | X11 selection and screensaver ([XWindowsClipboard](../../src/lib/platform/XWindowsClipboard.cpp), [XWindowsScreenSaver](../../src/lib/platform/XWindowsScreenSaver.cpp)) | Selection ownership and incremental property notifications drive cached and in-flight clipboard data. | Wayland input capture ([PortalInputCapture](../../src/lib/platform/PortalInputCapture.cpp)) | Portal session, zones and barriers precede capture. Activation ID scopes release. | Wayland remote desktop and libei ([PortalRemoteDesktop](../../src/lib/platform/PortalRemoteDesktop.cpp), [EiComputer](../../src/lib/platform/EiComputer.cpp), [EiKeyState](../../src/lib/platform/EiKeyState.cpp)) | A portal starts a session and transfers the EIS file descriptor to the event thread. ## Changes and evidence

| Finding | Prior event order and result | Updated behavior and check |
| --- | --- | --- |
| Confirmed by local sockets. IPC retry outlived cancellation. | Failed socket open scheduled an anonymous 500 ms callback. Disconnect changed the state but left the callback able to reopen the socket. | One owned timer follows the retry phase and is stopped on disconnect. Local socket tests also verify automatic retry when a server appears. |
| Confirmed by local sockets. Partial IPC bytes outlived the connection. | A peer sent a partial frame. On explicit reconnect those bytes prefixed the next peer's `hello`. The GUI could wait indefinitely. | Disconnect clears the receive buffer. The parser scans each received batch by offset and keeps only a trailing partial frame. The reconnect test observes a fresh handshake. |
| Confirmed by local sockets. IPC had no reliable handshake completion on peer loss. | Socket open installed a version exchange while the old transport error callback could still schedule a retry. A peer closing before `hello` could leave the caller without a failure signal. A silent peer had no deadline. | Transport retry and version exchange have distinct phases. Closing during the exchange ends it once. A five-second hello deadline reports a silent peer. Tests cover both, plus the mismatch-to-Stop-to-bye path. |
| Confirmed by source and a synchronized buffer test. Event readiness preceded event transfer. | The consumer published ready before draining. Producers selected a buffer by reading the flag outside its lock and could race the drain. A waiter could return before startup events reached the backend. | A single critical section transfers the FIFO and publishes readiness. The test blocks the transfer and checks that a waiter remains blocked until the transfer completes. The existing ten-second readiness budget is now enforced by a predicate wait. |
| Confirmed by source. Delayed switching could retain a removed destination. | Candidate lifetime used the active-peer removal check. A different, pending destination could remain selected as its membership ended. | Cancellation matches the pending destination independently of the current input destination. Both graceful closing and active-client disconnect pass through the cancellation path. Native edge crossing and client removal remain acceptance checks. |
| Equivalent on the wire. Clipboard sending copied each data substring twice before enqueueing. | The chunker constructed a temporary string, then copied its bytes into the event-owned chunk. | A view supplies the same bytes directly to owned storage. A wire-byte test covers multiple chunks, embedded zero bytes, an empty transfer and delivery after the source string has been destroyed. The receiver's state and limits follow the existing path. |

## Open observations

- **Confirmed by source, GUI process intent.** Stop cancels the visible
  `Starting` phase, while a queued daemon-connected callback still holds the
  command it was going to send. In desktop mode Stop during `RetryPending`
  can enter `Stopping` after the old process has already exited. These need a
  process-level contract for canceled starts, mode changes and late exit/IPC
  notifications. The IPC client timer fix concerns connection attempts only.
- **Confirmed by source, log tail.** An open failure leaves the target filename
  set, so requesting the same path skips reopening. Truncation or replacement
  also requires offset and watch recovery. A temporary-file rotation test is
  the appropriate boundary.
- **Likely, Wayland callback ownership.** Input capture re-enable and remote
  desktop reconnect schedule GLib sources with a raw owner pointer. Their native
  lifetime across portal close and teardown depends on which context can still
  dispatch and when sources are canceled. The matching native lifecycle should
  be traced before changing ownership or re-enable behavior.
- **Smell, queue timers.** Timer insertion and deletion use the queue mutex.
  Expiry and next-deadline reads assume event-loop ownership. Any new off-loop
  timer producer needs an explicit ownership and wakeup contract.
- **Smell, server-side local IPC framing.** The read loop assumes complete lines
  per socket read. It drops a trailing partial line. This audit changed GUI
  client framing. Server-side buffering and replay need separate checks across
  normal startup, shutdown and multiple peers.
- X11 incremental-selection cancellation, Windows secure desktop changes,
  Wayland permission revocation, native macOS Dock crossing and rapid
  reentry still depend on the OS and hardware. The inventory documents source
  ownership for those boundaries. Verification of interleavings, peer
  compatibility and installed-app behavior requires those environments.
